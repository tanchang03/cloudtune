## 1. 总体架构

**核心设计原则：纯客户端直连。** 没有自建后端服务器 —— 所有请求由客户端直接发往各网盘官方开放 API。
这条原则不是技术偏好，而是合规硬约束（见审计报告 §5）。

## 2. 统一数据模型

### 2.1 Track（统一曲目）

```dart
class Track {
  final String id;          // 合成主键: "${provider}:${fileId}"
  final DriveProvider provider;   // quark | aliyun | baidu
  final String accountId;   // 支持同网盘多账号
  final String fileId;      // 网盘侧文件 ID
  final String name;        // 原始文件名
  final String? path;       // 完整路径（用于展示与分组）
  final String? parentId;
  final int size;           // 字节
  final DateTime? modifiedAt;
  final String ext;         // mp3 / flac / ...
  // 元数据（可空，扫描后异步补全）
  final TrackMeta? meta;    // title / artist / album / coverUrl / durationMs
}
```

**关键点**：`Track` 里**不存直链**。直链是易失的（阿里云盘 15 分钟），必须每次播放前实时换取。

### 2.2 数据表设计（Drift）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `accounts` | id, provider, nickname, avatar, expireAt, enabled | token 本体存 SecureStorage，表里只存引用与元信息 |
| `tracks` | id, provider, accountId, fileId, name, path, size, mtime, ext, title, artist, album | 主索引表 |
| `favorites` | trackId, createdAt | 喜欢 |
| `play_history` | trackId, playedAt, playCount | 最近播放 |
| `scan_cursor` | accountId, dirId, dirPath, cursor, state, updatedAt | **断点续扫**核心 |
| `dir_cache` | accountId, dirId, parentId, name | 目录树缓存，避免重复遍历 |

索引：`tracks(provider, accountId)`、`tracks(ext)`、`favorites(createdAt)`。

## 3. 网盘适配器抽象（多云盘的关键）

新增一家网盘 = 实现一个接口，上层零改动。

```dart
abstract class CloudDriveAdapter {
  DriveProvider get provider;

  // ── 授权 ──
  Future<AuthSession> buildAuthUrl({required String redirectUri});
  Future<AuthSession> exchangeCode(String code, String state);
  Future<AuthSession> refresh(AuthSession current);
  Future<UserInfo> getUserInfo(AuthSession s);
  Future<void> revoke(AuthSession s);

  // ── 遍历 ──
  /// 列目录。注意：夸克不支持，需抛 UnsupportedError 并由上层走 search 兜底
  Future<DirPage> listDir(AuthSession s, {required String? parentId,
      required String? cursor, int limit = 100});

  /// 搜索。所有网盘都支持，作为夸克的遍历主通道
  Future<DirPage> search(AuthSession s, {required String keyword,
      String? cursor, int limit = 100, String? category});

  Future<FileDetail> fileInfo(AuthSession s, {required String fileId});

  // ── 播放 ──
  /// 换取直链 + 播放所需的 HTTP 头
  Future<StreamTicket> resolveStreamUrl(AuthSession s, {required String fileId});

  /// 该网盘的能力声明，供 UI 与编排层决策
  Capabilities get capabilities;
}

class StreamTicket {
  final Uri url;
  final Map<String, String> headers;  // 百度必须带 User-Agent
  final DateTime? expireAt;
}

class Capabilities {
  final bool supportsListDir;      // 夸克 = false
  final bool supportsSearch;       // 全 = true
  final bool requiresCustomHeaders;// 百度 = true（Web 端致命）
  final int maxPageSize;           // 夸克 100 / 阿里 100 / 百度 1000
  final Duration urlTtl;           // 阿里 15min
  final RateLimitPolicy rateLimit;
}
```

`Capabilities` 是这套设计的枢纽：UI 可以据此显示「该网盘不支持目录浏览」，
编排层可以据此切换遍历策略，播放层可以据此判断 Web 端能否播放。

### 3.1 三家网盘的接口差异（已核实）

| 能力 | 夸克网盘 | 阿里云盘 | 百度网盘 |
|---|---|---|---|
| 开放平台 | `open.quark.cn`，**内测中、文档未公开** | `openapi.alipan.com`，正式 | `pan.baidu.com/union`，正式 |
| 鉴权 | 签名头 + OAuth<br>`x-pan-token = SHA256(METHOD&PATH&TM&KEY)` | 标准 OAuth2.0 Bearer | 标准 OAuth2.0 Bearer |
| 列目录 | ❌ **无 list_dir** | ✅ `POST /adrive/v1.0/openFile/list` | ✅ `GET /rest/2.0/xpan/file?method=list` |
| 搜索 | ✅ `POST /agent/v1/file/search`（size 1–100） | ✅ `POST /adrive/v1.0/openFile/search` | ✅ `GET .../xpan/file?method=search` |
| 直链 | ✅ `POST /open/v1/file/multi_get_download_url` | ✅ `POST /adrive/v1.0/openFile/getDownloadUrl` | ✅ `GET .../xpan/multimedia?method=filemetas&dlink=1` |
| 直链有效期 | 未公开 | **15 分钟**（普通应用） | 未公开，通常较短 |
| 播放额外要求 | 取下载数据需带 Cookie `x_pan_access_token` | 无 | **必须带 `User-Agent: pan.baidu.com`** |
| 限流 | 未公开（有风控，签名错误 → errno 10001） | list 10s/40次；getDownloadUrl 10s/10次；其他 15 QPS；分段下载并发 3/s | 未公开具体值 |
| 准入 | 需申请内测 | 开发者报名即用（默认「普通应用」） | 需账号认证 |

### 3.2 夸克接入模式对比（含新增「本机会话复用」）

夸克是唯一需要多条接入路线的网盘。按稳定性从高到低：

| 模式 | 做法 | 稳定性 | 平台 | 适用场景 |
|---|---|---|---|---|
| **A. 官方开放平台** | 申请 `open.quark.cn` 内测，走官方签名 + OAuth | 高 | 全平台 | ✅ 正式路线（目标态） |
| **B. 逆向签名** | 复刻 `SHA256(METHOD&PATH&TM&SIGN_KEY)` + OAuth | 低 | 全平台 | PoC / 兜底 |
| **C. Cookie 手动导入** | 用户手动粘贴 Cookie | 极低 | 全平台 | ❌ 已否决 |
| **D. 本机会话复用** | 读取本机夸克客户端/浏览器落盘的会话凭据 | 低 | **仅桌面端** | PoC 快捷通道 / 桌面端补充 |

#### 模式 D 的实现依据（已在本机实测）

> **📌 公开版本已脱敏（2026-09-24）**
> 本节原先记录了本机夸克客户端凭据落盘的具体路径、Chromium `cookies` 表结构，
> 以及从系统钥匙串取密钥解密的做法。这些内容与「读取其他应用私有凭据」的操作步骤
> 直接对应，公开仓库中不再保留具体做法，**只保留结论**。
> 该通道**从未进入发布路径**，原因见 `docs/03` §7.1 的四条硬限制。

夸克桌面端有三处独立的凭据落盘位置（旧 Electron 客户端 / 夸克浏览器 / 网盘客户端），
实测结论：

| 数据源 | 加密 | 最近写入 | 可用性 |
|---|---|---|---|
| 旧 Electron 客户端 | **明文** | 2026-04-25 | 读取最易，但会话已过期 |
| 夸克浏览器 | Chromium v10 加密 | 当天 | 会话最新鲜，但需解密 |
| 夸克网盘客户端 | Chromium v10 加密 | 2026-04-25 | 需解密，且已过期 |

- 三处均为标准 Chromium `cookies` 表结构（SQLite），字段
  `host_key / name / value / encrypted_value`。
- 明文那份的 `encrypted_value` 长度为 0，`value` 列直接可读。
- 加密那两份的密钥由系统钥匙串托管。
- 关键 cookie：`__pus` / `__puus`（会话主令牌）、`__kuus` / `__uus`（会话）、`__uid`、`tfstk`、`b-user-id`。
- 三处都出现 `access-open.quark.cn | _UP_RI_`，说明浏览器访问过夸克开放平台域。

#### PoC 实测补充（2026-09-23，`poc/` 目录）

- **接口链路已验证**：`drive-pc.quark.cn/1/clouddrive/config` 与 `/member` 返回语义正确的
  `HTTP 401 / code=31004 token invalid`，说明域名、请求头、`pr=ucpro&fr=pc` 参数、
  Cookie 组装方式全部正确 —— **接口层无未知数**。
- **明文库是遗留产物**：`quark-cloud-drive/` 属旧版客户端（`config.json` 内
  `appVersionForHost: 3.24.0`），当前客户端二进制不含该路径字串，
  升级后已改用 `QuarkCloudDrive/`，**明文库不会再被刷新**。
- **加密方案为自研**：穷举候选密钥 × 多种密钥派生参数 × 多种分组模式组合（共 700 次）
  全部落空，`Local State` 中也没有标准 Chromium 的密钥字段。
  **结论：非标准 Chromium 方案，未破解成功，继续投入性价比低。**
- **因此模式 D 的会话获取改用「手动提供 Cookie」通道**（用户在浏览器登录后，
  自行从开发者工具复制 `__pus` / `__puus` 粘贴进应用），已实现并验证代码路径。
- 研究期的 PoC 脚手架（`poc/`）**不随本仓库公开**，原因见根目录 `.gitignore` 中的说明。

#### 全链路实测结果（2026-09-23，已跑通）

| 环节 | 结果 |
|---|---|
| 会话有效性 | ✅ `HTTP 200 code=0` |
| 递归列目录 | ✅ 250 目录 / 2592 文件 / **444 首音乐 / 37.23 GB** |
| 搜索 | ✅ `mp3` / `flac` / 歌手名 各返回 50 项 |
| 取直链 | ✅ `code=0`，返回 `download_url` |
| **Range 播放** | ✅ **带 Cookie → `HTTP 206` + `Accept-Ranges`，首字节 `fLaC`** |
| **体积上限** | ⚠️ **~50 MB 硬限制**（`code=23018`），9 种变体均无法绕过 |

**两条必须写进实现的硬约束**：

1. **直链必须携带 Cookie**。请求头矩阵 11 种组合实测：裸请求 / 仅 Referer / 仅 UA 全部
   `HTTP 412 Precondition Failed`；**任何带 Cookie 的组合**才返回 `206`。
   → 播放引擎必须使用**带自定义请求头的 AudioSource**：
   ```dart
   AudioSource.uri(ticket.url, headers: {
     'Cookie': ticket.cookieHeader,
     'User-Agent': kQuarkUA,
     'Referer': 'https://pan.quark.cn/',
   })
   ```
   这也是 `StreamTicket` 必须携带 `headers` 字段的原因（见 §2.1）。

2. **~50 MB 单文件体积上限**（账号为 SUPER_VIP，非会员限制）。
   → `Track` 需新增 `playable` 派生字段（`size <= 50MB`），
     `ShufflePlay` 的取样范围必须限定为「当前筛选 ∩ 可播集合」。

#### 实测校准的关键字段语义（易踩坑）

- **`dir: true/false`** 才是目录布尔位
- **`file_type`: `0` = 目录，`1` = 文件**（反向理解会导致文件被当目录、BFS 队列爆炸）
- `format_type` = MIME，可作音频识别辅助信号（如 `audio/flac`）
- `fid` / `pdir_fid` = 文件 ID / 父目录 ID

#### 实测端点清单

| 用途 | 方法 | 路径 | 必需参数 |
|---|---|---|---|
| 配置 | GET | `/1/clouddrive/config` | `pr=ucpro&fr=pc` |
| 用户信息 | GET | `/1/clouddrive/member` | `pr=ucpro&fr=pc&uc_param_str=` |
| 列目录 | GET | `/1/clouddrive/file/sort` | `pdir_fid`、`_page`、`_size`、`_fetch_total`、`_sort`、`_is_hl` |
| 搜索 | GET | `/1/clouddrive/file/search` | `_key`、`_page`、`_size`、`_fetch_total`、`_sort` |
| 取直链 | POST | `/1/clouddrive/file/download` | body `{"fids": [...]}` |

错误码：`0` 成功 · `31001` require login · `31004` token invalid ·
`23018` download file size limit · `10001` 签名失败（开放平台专用）

#### 模式 D 的四条硬限制（必须写进产品约束）

1. **平台锁死**：仅 macOS / Windows 可行。iOS 沙箱无法读取其他 App 数据；Android 需 root。
   → 与「Flutter 全平台」直接冲突，**移动端永远不可用**。
2. **本机锁死**：凭据是本机产物，无法分发、无法跨设备同步，每个用户需各自在本机准备一次。
3. **生命周期不可控**：会话会过期、会静默轮换，客户端一刷新即失效，需用户反复重新获取。
4. **合规等级上升**：已不属于「使用官方开放 API」，而是读取其他应用私有凭据。

#### 定位结论

模式 D 定位为 **`LocalSessionProvider`：仅开发期 PoC 使用的临时通道**，
在代码中显式标记 `experimental`，**不进入正式发布路径**，不写入面向用户的产品功能清单。

它的价值是：**在没有内测资格时，以最小成本证伪「夸克里的音乐能否列出、直链能否播放」**，
同时反向验证 `CloudDriveAdapter` 抽象是否真的够用——
若新增此模式无需改动上层任何代码，则说明抽象正确。

## 4. 播放引擎设计

### 4.1 选型

| 平台 | 后端 | 说明 |
|---|---|---|
| Android | ExoPlayer (media3) | just_audio 官方支持，支持自定义请求头 |
| iOS / macOS | AVPlayer | just_audio 官方支持 |
| Windows | `just_audio_windows`（社区） | 需单独引入，功能基本可用 |
| Linux | `just_audio_media_kit` | 基于 libmpv |
| Web | HTML5 Audio | ⚠️ **无法自定义请求头、受 CORS 限制** |

配套：`audio_service` 提供后台播放、通知栏、锁屏控制、耳机线控（移动端）。

### 4.2 直链自愈（StreamingAudioSource）

```
播放某 Track
  → 查内存 ticket 缓存（key = trackId）
     ├─ 命中且未过期 → 直接播
     └─ 未命中/已过期 → 调 adapter.resolveStreamUrl()
  → 起播，记录起播位置
  → 监听播放错误
     ├─ 403 / 401 / URL 过期 → 失效缓存 → 重新 resolve → seek 回原位置续播
     └─ 连续失败 3 次 → 跳过该曲，提示「该文件暂时无法播放」
```

**要点**：不做「整首下载再播」。`just_audio` 原生支持 HTTP Range 边下边播。

### 4.3 随机播放算法

```
1. 取当前筛选范围内的 Track 全集
2. Fisher-Yates 洗牌 → 得到本轮队列
3. 若上一轮队尾 == 本轮队首 → 交换本轮队首与随机位置，避免"连着同一首"
4. 权重调整（可在设置里关闭）：
     weight = 1.0
            + 1.0  (若已喜欢)
            + 0.3  (若 30 天内播放过，随天数衰减到 0)
            - 0.5  (若 1 小时内刚播过)
   按权重做无放回加权抽样，生成队列
5. 队列耗尽 → 回到第 2 步
```

**为什么不用 `Random().nextInt()` 裸随机**：裸随机会出现「一首歌反复出现、另一首半年听不到」，
体验差。洗牌队列 + 权重是成熟做法。

## 5. 扫描与限流编排

### 5.1 限流器（必须，否则会触发风控）

```dart
class RateLimiter {
  // 令牌桶，按 (provider, endpoint) 维度独立限流
  // 阿里云盘: list = 40/10s, getDownloadUrl = 10/10s, 其他 = 15 QPS
  // 夸克/百度: 保守设 5 QPS，并指数退避
  Future<T> run<T>(String bucket, Future<T> Function() task);
}
```

默认并发策略：
- 目录遍历并发：**4**（用户可在设置里调低到 1）
- 直链换取并发：**2**（阿里云盘限 10s/10 次，必须克制）
- 失败重试：指数退避 `1s → 2s → 4s`，最多 3 次；429 则退避 `5s → 15s → 45s`

### 5.2 遍历策略（因网盘而异）

| 网盘 | 主策略 | 说明 |
|---|---|---|
| 阿里云盘 | `openFile/list` 递归 + marker 分页 | 标准做法，可靠 |
| 百度网盘 | `xpan/file?method=list` 递归 | 标准做法 |
| 夸克网盘 | `agent/v1/file/search` 按分类 + 关键词分页 | **无 list_dir，只能搜** |

夸克侧的具体做法：用 `category` 参数按音频分类枚举 + 用常见关键词（歌手名/专辑名/扩展名）
补扫，再用 `file/info?fetch_full_path=1` 拿完整路径。**这是一种近似遍历，无法保证 100% 覆盖**，
必须在 UI 上向用户如实说明（见审计报告 §3.2）。

### 5.3 断点续扫

`scan_cursor` 表逐目录记录状态（`pending / scanning / done / failed`）。
中断后重入时从 `pending` 继续，已 `done` 的目录直接跳过。
每个目录扫描完成后立即批量落库（事务批量 200 条），避免中断丢数据。

## 6. 错误归一化

把三家各不相同的错误码收敛成一套，上层统一处理：

| 归一化错误 | 夸克 | 阿里云盘 | 百度 | 处理策略 |
|---|---|---|---|---|
| `Unauthorized` | errno 11001 | `AccessTokenInvalid` | `-6` | 静默 refresh，失败则提示重新授权 |
| `RateLimited` | — | HTTP 429 | `-8` | 退避重试，降低并发 |
| `NotFound` | errno 31001 | `NotFound` | `-9` | 从索引中标记失效 |
| `UrlExpired` | HTTP 403 | HTTP 403 | HTTP 403 | 重新 resolve 直链并续播 |
| `PermissionDenied` | — | `Forbidden` | `-7` | 提示权限不足，引导重新授权 |
| `SignatureError` | errno 10001 | — | — | 检查签名算法与系统时间（时钟偏移会导致签名失败） |

## 7. 平台能力矩阵（Flutter 全平台的真话）

| 能力 | Android | iOS | macOS | Windows | Linux | Web |
|---|---|---|---|---|---|---|
| 在线播放 | ✅ | ✅ | ✅ | ✅ | ✅ | ⚠️ 受限 |
| 自定义请求头（百度必需） | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |
| 后台播放/锁屏控制 | ✅ | ✅ | ✅ | ⚠️ 托盘 | ⚠️ | ❌ |
| 本地索引库 | ✅ | ✅ | ✅ | ✅ | ✅ | ⚠️ IndexedDB |
| 安全存储 token | ✅ | ✅ | ✅ | ✅ | ⚠️ | ❌ |
| 桌面快捷键/迷你窗 | — | — | ✅ | ✅ | ✅ | — |
| 夸克本机会话复用（模式 D） | ❌ | ❌ | ✅ | ✅ | ⚠️ | ❌ |

**结论**：全平台**不是**能力等价的。建议分级承诺：

- **第一梯队（全功能）**：Android、iOS、macOS、Windows
- **第二梯队（基本可用）**：Linux（后台播放较弱）
- **第三梯队（仅浏览/管理）**：Web（不承诺播放，或只播 CORS 友好的阿里云盘直链）
